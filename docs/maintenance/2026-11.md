# 2026-11 维护记录

## 2026-11-24 · 确定工作台的设计方向

- **背景**：需求从记忆系统讨论收敛为个人多项目的 AGENTS.md、模块约束、维护来由和人审提案管理。用户要求随模型能力增强减少脚手架，避免堆叠完整框架。
- **结果**：深入检查 CloudCLI、Compound Engineering、ECC 与用户补充的 mini-trellis 固定提交，最终建议以 mini-trellis core 与文档能力为底座，吸收 CE 的经验筛选及精简方法和 ECC 的提炼信号，CloudCLI 延后作为可选入口。形成[整体设计](../design.md)与[源码审查](../research/source-review.md)。这仍是设计建议，尚未实现应用或正式导入上游产品代码。
- **原因**：mini-trellis 已有独立 core、原文发现、来源及日志，比以 CE 为底座更少重做；其确认后直接写入仍要改成差异审核。CloudCLI 的宿主较重，CE/ECC 不再作为额外运行系统。
- **验证**：CE 五项探针、ECC 两项探针与 20 项相关性测试通过；mini-trellis 123 项核心测试与三项真实日志探针通过。研究台账结构和文档链接在交付前检查。未做任何工作台功能测试，详见[验证边界](../research/source-review.md)。
- **后续**：先实现文件登记与只读展示，再实现一文件提案审核和恢复，最后接当前 code agent 的自动提炼与维护留档。自动提炼的实际宿主触发能力与准确率需要在实现时验证。
- **版本**：mini-trellis `0f37e0f2`；CE `fcb5e3a`；ECC `4adeee67`；CloudCLI `b6959148`，完整提交号见源码审查。当前没有应用发布版本或相关提交引用。

## 2026-11-24 · v0.1 最小闭环实现

- **背景**：用户确认 mini-trellis 底座、蓝白文档工作台与17张交互图，要求完成实现和首次远程推送。默认启动真实空工作区，另设隔离演示。
- **实际结果**：一个本机 Node 进程连接原生页面、文件存储和 CLI；支持登记、来源配置、分层阅读、搜索、提案编辑与差异审核、拒绝、冲突重提、日志和工程决策详情。仓库内 Skill 按需读取上下文和提交候选，不提供批准命令。
- **取舍**：mini-trellis-core 通过公开 npm 包使用；CE/ECC 与 write-notes-like-deepseek 贡献方法和界面参考，不再整仓拼装。不引入数据库、模型服务、CloudCLI 或前端框架。既有 mini-trellis 日志只读兼容，新记录写配置目录。
- **恢复与边界**：写入绑定原文和候选版本；候选保存、拒绝与只读查询不改规则。日志目标不能由记录输入重定向；批准中断后冻结候选并提供补齐记录入口。真实进程退出和并发 CLI 写入均有回归。
- **验证**：32项 Node／HTTP／CLI 测试；18项浏览器检查，覆盖17类主要操作和状态，产生20张截图。Skill 结构校验通过；视觉检查见 [design-qa](../../design-qa.md)。构建生成独立运行目录；干净目录仅安装生产依赖后，静态资源、登记、审核写入与打包 Skill 均通过复核。
- **未决**：未评估真实对话自动提炼准确率；不实现工程笔记归档写入、后台会话采集或跨设备同步。系统级文件隔离不在当前范围。
- **版本**：应用0.1.0，mini-trellis-core0.4.2；锁文件固定实际依赖版本，Playwright仅用于开发验收。

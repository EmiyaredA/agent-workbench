# 2026-11 维护记录

## 2026-11-24 · 确定工作台的设计方向

- **背景**：需求从记忆系统讨论收敛为个人多项目的 AGENTS.md、模块约束、维护来由和人审提案管理。用户要求随模型能力增强减少脚手架，避免堆叠完整框架。
- **结果**：深入检查 CloudCLI、Compound Engineering、ECC 与用户补充的 mini-trellis 固定提交，最终建议以 mini-trellis core 与文档能力为底座，吸收 CE 的经验筛选及精简方法和 ECC 的提炼信号，CloudCLI 延后作为可选入口。形成[整体设计](../design.md)与[源码审查](../research/source-review.md)。这仍是设计建议，尚未实现应用或正式导入上游产品代码。
- **原因**：mini-trellis 已有独立 core、原文发现、来源及日志，比以 CE 为底座更少重做；其确认后直接写入仍要改成差异审核。CloudCLI 的宿主较重，CE/ECC 不再作为额外运行系统。
- **验证**：CE 五项探针、ECC 两项探针与 20 项相关性测试通过；mini-trellis 123 项核心测试与三项真实日志探针通过。研究台账结构和文档链接在交付前检查。未做任何工作台功能测试，详见[验证边界](../research/source-review.md)。
- **后续**：先实现文件登记与只读展示，再实现一文件提案审核和恢复，最后接当前 code agent 的自动提炼与维护留档。自动提炼的实际宿主触发能力与准确率需要在实现时验证。
- **版本**：mini-trellis `0f37e0f2`；CE `fcb5e3a`；ECC `4adeee67`；CloudCLI `b6959148`，完整提交号见源码审查。当前没有应用发布版本或相关提交引用。

## 2026-11-24 · v0.1 最小闭环实现

- **背景**：用户确认 mini-trellis 底座、蓝白文档工作台与17张交互图，要求完成实现和首次远程推送。默认启动真实空工作区，另设隔离演示。
- **实际结果**：一个本机 Node 进程连接原生页面、文件存储和 CLI；支持登记、来源配置、分层阅读、搜索、提案编辑与差异审核、拒绝、冲突重提、日志和工程决策详情。仓库内 Skill 按需读取上下文和提交候选，不提供批准命令。
- **取舍**：mini-trellis-core 通过公开 npm 包使用；CE/ECC 与 write-notes-like-deepseek 贡献方法和界面参考，不再整仓拼装。不引入数据库、模型服务、CloudCLI 或前端框架。既有 mini-trellis 日志只读兼容，新记录写配置目录。
- **恢复与边界**：写入绑定原文和候选版本；候选保存、拒绝与只读查询不改规则。日志目标不能由记录输入重定向；批准中断后冻结候选并提供补齐记录入口。真实进程退出和并发 CLI 写入均有回归。
- **验证**：32项 Node／HTTP／CLI 测试；18项浏览器检查，覆盖17类主要操作和状态，产生20张截图。Skill 结构校验通过；视觉检查见 [design-qa](../../design-qa.md)。构建生成独立运行目录；干净目录仅安装生产依赖后，静态资源、登记、审核写入与打包 Skill 均通过复核。
- **未决**：未评估真实对话自动提炼准确率；不实现工程笔记归档写入、后台会话采集或跨设备同步。系统级文件隔离不在当前范围。
- **版本**：应用0.1.0，mini-trellis-core0.4.2；锁文件固定实际依赖版本，Playwright仅用于开发验收。


## 2026-11-24 · 看板布局收紧

- **背景**：用户指出提案页顶部留白和重复说明过多，补充工程决策看板作为密度参考。
- **结果**：合并桌面项目标题、导航与搜索；提案和日志的筛选与操作同行，收紧项目侧栏、列表、差异行高和总览表格。维护摘要限两行，完整内容仍在详情中读取。
- **取舍**：沿用原生页面、字体和图标；不新增依赖或统计卡片，不修改存储与审核行为。正文仍保留可读字号，窄屏导航按空间换行。
- **验证**：同为1470×900的提案页，页头约144px降到59px，差异起点约465px提前到222px。18项隔离浏览器检查、源码检查与构建通过；1100／1024／768／390宽度无横向溢出。视觉证据见 [design-qa](../../design-qa.md)。


## 2026-11-24 · Skill 原文阅读与全局入口独立

- **背景**：用户要求 Skill 页直接展示 SKILL.md；全局约束面向全部项目，不应出现在某个项目的作用域切换中。
- **结果**：Skill 页通过固定只读接口读取实际文件，默认呈现 Markdown 正文，提供含元数据的完整原文及复制；移除重复功能介绍和单独拼接的命令。项目内仅显示项目／模块，全局偏好从侧栏独立打开，标题、提案与日志均使用全局上下文。
- **兼容**：旧的“项目ID＋全局scope”链接回到该项目约束；Code Agent 的 context 仍组合全局和项目约束，调整仅涉及看板的信息归属。
- **验证**：32项 Node／HTTP／CLI 测试、18项浏览器检查通过；覆盖固定 Skill 文件读取、复制与原文一致、独立全局入口、返回项目和旧链接。产出21张验收截图。源码检查和构建通过。


## 2026-11-24 · 固定目录与索引读取

- **背景**：用户希望约束按固定目录维护和读取，并明确要求使用本项目名称，而不是上游 .trellis 命名。
- **结果**：新项目默认根 AGENTS.md、.agent-workbench/rules/index.md 与模块正文、docs/maintenance。默认值集中在 src/layout.mjs；登记与设置展示当前约定，旧目录映射放兼容选项。补充项目入口和模块索引模板。
- **读取**：context 返回全局／项目正文、已存在的模块根索引正文和模块文件列表；模块正文按需读取。取消常规整库 docs／README／研究发现，保留既有日志及决策来源。关联用普通 Markdown 链接，不引入依赖图或第二套元数据协议。
- **兼容**：不迁移已有真实项目、不改现存全局文件或项目 AGENTS.md。mini-trellis 仅提供依赖原语和既有目录兼容；新的默认结构使用 agent-workbench 自身命名。模板采用仍经具体差异审核。
- **验证**：34项功能测试和18项浏览器检查通过；回归固定目录、索引先行、无关文档排除、旧映射独占、Skill原文复制与项目审核闭环。源码检查、构建通过。目录与来源依据见 [目录约定](../directory-convention.md)。


## 2026-11-24 · 统一约束列表与丰富演示

- **背景**：用户认为示例内容偏少，希望直接展示全部约束，不再区分项目／模块两个视图。
- **结果**：根 AGENTS.md、索引与其他规则在同一列表直接打开；删除作用域切换与相关路由状态，统一显示为项目约束，全局仍独立。侧栏只显示当前文件的待审建议，避免把其他文件的提案当成当前差异。
- **演示**：工作台、作品站、API服务三种背景，22份约束文档、11条提案（6待审、2写入、2拒绝、1冲突）、20条维护记录、13份四种生命周期的决策笔记。内容按各项目分别编写，不复制同一份模板；所有项目背景和历史明确标为示例。
- **隔离**：默认演示更新到 .runtime/demo-v2，旧演示目录保留。初始化完成后不重复覆盖使用者的示例编辑，也不向已登记真实项目的工作区播种。真实项目读取协议和按需上下文不变。
- **验证**：36项功能测试、18项隔离浏览器检查与构建通过。另在实际演示逐页复核统一列表、三项目差异、审核状态、跨月日志、决策详情和390／768／1024宽度，生成13张截图，报告位于忽略目录 .local/rich-demo/report.json。


## 2026-11-24 · 约束按真实目录树呈现

- **背景**：用户希望文件栏按实际目录组织，避免每个文件重复显示相同路径。
- **结果**：以目录树显示根入口和登记约束，文件夹可展开／折叠，文件行只显示名称，完整路径可悬停查看。展开状态按项目在当前页面保留，跳转到隐藏文件时自动展开父目录。
- **取舍**：使用原生details／summary和已有图标，无新依赖，不改变读取范围。窄屏使用限高滚动目录，并保持当前文件可见。
- **验证**：18项浏览器检查和构建通过；覆盖折叠状态重渲染后保持、键盘展开和完整审核流程。另在实际演示检查深链接展开、桌面与390宽度，证据位于 .local/directory-tree/。


## 2026-11-24 · 自定义下拉与移除总览

- **背景**：用户指出原生下拉箭头过于靠边，并认为在已选项目内显示跨项目总览会混淆归属，要求移除总览。
- **结果**：月份筛选和窄屏项目切换共用自定义菜单，箭头右侧12px内边距，统一边框、选中态和勾选图标；支持方向键、Home／End、Enter、Esc、Tab和菜单外点击。移除总览页和标签，项目内仅约束、提案、维护记录，旧总览链接按当前项目约束处理。
- **保留**：空工作区的登记引导、全局独立入口和实际恢复警告仍可访问。未新增依赖或修改存储接口。
- **验证**：18项浏览器检查、源码检查与构建通过，产生23张交互截图。实际丰富演示另验证三个月份筛选、移动菜单边界、旧总览链接和三项导航；证据在 .local/dropdown-ui/、.local/navigation-ui/。


## 2026-11-24 · 维护记录的融合调研

- **背景**：用户希望综合write-notes与mini-trellis，明确约束、审核和迭代维护三块职责；本轮要求先调研。
- **结论**：用迭代记录保存实际变化、验证与后续，用决策笔记保存理由和备选，同一决定可被多次迭代引用。保留现有目录和按需读取，不复制正文、不扩展为全量记忆平台。
- **发现**：文件首次提出日与维护发生日不能混用；归档封存后不能再加替代标记；移动笔记仍需检查日志链接。当前普通record缺少调用方幂等键，外部直接改文件也没有自动送审和已审基线。
- **验证**：独立仓库探针验证上游封存与篡改检测、旧链接残留、发现范围，以及当前context读取外部修改和record重复行为。详见 [调研](../research/maintenance-integration.md) 与 [结果](../research/maintenance-verification.json)。应用功能未变，未重复运行应用测试。


## 2026-11-24 · 保留工程决策四视图并关联实际迭代

- **背景**：用户希望保留架构基线、演进时间线、避坑智库、决策清单，并吸收 mini-trellis 的改动／验证／后续交接方式；本轮选择决策只读、迭代可写。
- **结果**：四视图读取同一批项目文件，识别明确链接、替代与归档；实际迭代与决策首次提出事件分开标注。桌面详情侧栏、窄屏焦点抽屉支持双向跳转、原文及交接摘要。新增记录可关联已有决定，operationId 支持跨进程／跨月重试，同键不同内容冲突。
- **取舍**：不新增生产依赖，不改决策正文和状态，不实现封存写入或外部变更自动送审。mini core 的既有前导标记与发现范围不覆盖 write-notes 的标题后元信息，工作台在显式登记范围内补充只读适配。
- **隔离**：演示 v3 补充六类决定与明确关联，旧 v2 和真实项目保持原样；不复写用户示例编辑。
- **验证**：43项 Node／HTTP／CLI 测试、18项现有界面回归、14项维护专项浏览器检查通过；构建通过。专项13张截图及报告位于 .local/maintenance-ui/，包括响应丢失后重试、关联跳转、归档／替代、月份／类别／状态筛选、键盘和390宽度。
- **边界**：历史封存清单不在本轮校验；规则读取仍是磁盘现状，最后已审快照与外部改动入队尚未实现。本轮不提交或推送。


## 2026-11-24 · 页面工具栏移入顶部

- **背景**：用户指出提案状态筛选与维护四视图独占正文一行，顶部主导航右侧仍有可用空间。

## 2026-11-24 · 四视图筛选与统计合为紧凑一行

- **背景**：用户希望月份、类别、统计和搜索合并一行，上下留白进一步收紧，四个维护视图一致处理。
- **结果**：统计移入筛选工具栏，移除正文中的重复计数；统计随当前筛选结果更新。桌面控件同行，工具栏约41px，正文标题上方间距10px；窄屏按空间换行，不引入横向溢出。
- **验证**：18项原有浏览器回归、14项维护专项与构建通过。实际示例在1512／1280宽度逐一测量四视图，均单行且高41px；390宽度四视图无页面横向溢出。证据在 .local/compact-filters/。现有搜索用例补充等待结果渲染完成，避免检查上一帧的行数。

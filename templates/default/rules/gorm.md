## GORM 与模型建表

- 表结构由模型定义，事务内继续使用同一带 context 的事务句柄，检查错误与受影响行数；不使用 Save 覆盖整行。
- 参考 Go 项目由 `make db` 与自定义 tpls/model 生成模型、CreateTable，InitModels 登记所有表，准备 schema 前提／守卫；任一表建表失败则启动失败。模型文件按领域、缓存装饰器、设置、schema 守卫及明确只读聚合职责组织，不随意手写另一套模型。
- 参考默认 AutoMigrate 常开，用于新表／新列落库，不为了测试关闭。若项目已明确只用于新库、已有库先审核 SQL，保留其例外并在导入时核对冲突，不自动更改应用配置。
- 已有表的列、默认值、非空、删除、触发器或存量回填，同批提供 `docs/db-migration/<日期>/` 手工方案；它不是新迁移框架，应用不自动加载。按预检、schema、回填、验证分步，破坏性操作单独成文件，只在测试库演练；线上执行需另行授权。
- 生成前仅使用本地／测试连接，不将 DSN、库名或密码写进 Makefile。新表先生成登记后在独立新库／schema 验证，不能清共享库。
- 数据库层测试针对锁、条件更新、软删复活与并发扣减；专用环境变量缺失则跳过，使用生产同款建表入口建立一次性 schema，结束可清理该夹具，绝不指向共享库。

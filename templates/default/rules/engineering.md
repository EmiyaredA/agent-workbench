## 变更范围与依据

- 开发和测试只操作本地／测试环境；不得操作线上服务器、数据库、Redis 或部署，不确定环境时先询问。
- 新代码遵循现行约定，存量代码改到时再对齐，不借机重构无关内容。替代旧实现时同步处理旧入口，确需兼容先说明原因，不留两套同职责实现。
- 先复用现有能力，两个以上真实调用方再抽象；辅助模块以职责命名，不建立含义模糊的 util、helper、misc 杂物目录。
- 共享系统设置会影响其他实例。测试不擅自修改安全开关；涉及它们的改动先确认范围，在隔离环境验证并恢复测试设置。

## 身份、权限与配置

- 当前身份从可信请求上下文取得；角色、封禁、成员关系和会话以权威后端状态为准，可缓存但变更立即失效。不信客户端或令牌自行声明的角色，按 ID 操作必须校验归属与租户。
- 闸门遇到未知值、脏数据走拒绝侧；关闭检查必须显式配置并留下操作人与原因。风控项未填使用内置默认，显式 0 的含义由契约定义，不能与未配置混同。
- 密钥、口令、令牌、原始／密文凭据不进仓库、日志、审计、告警和截图，不给真实凭据写默认值。只提交脱敏配置示例。
- 启动项与运行期业务配置分开；密字段加密存储、管理端只显示已设置状态，不能回传完整值。会使既有身份失效的不可变密钥须明确生命周期，不能随意更换。

## 涉及金额、权益或状态时

- 金额与额度在所属业务服务／数据入口变更；使用明确的整数最小单位，不用浮点算钱。先乘后除，最终只取整一次；更细单位在系统设计中声明。
- 每次业务变动有唯一业务键并由唯一约束兜底；同键同内容返回首次结果，同键不同内容拒绝。库存、余额和状态迁移使用条件更新，检查受影响行数，不先查后整行覆盖。
- 多步写入在同一事务或明确锁边界内完成，失败整体回滚；先处理冷行、热点行尽量后置，缩短持锁时间。事务内不调用支付、短信、邮件、对象存储等外部系统。
- 金额及权限变化与审计同事务写入；高频预扣／结算等业务流水可按项目声明按请求 ID 留存，仅异常转审计，不能因此丢失业务事实。
- 价值或权限发放记录自身保存操作人、接收人、时间、原因、来源及必要审批人；变更保留历史并能在页面追溯，仅有审计日志不够。
- 枚举集中定义并保持持久化取值稳定，未知值不默认放行；修改已有状态、价格和权限规则时核对历史数据与所有调用方。

## 错误、日志与留存

- 对外返回稳定的业务错误与本地化消息，内部细节只进受控日志；错误码、引用码只追加，不重排或改旧含义。新增错误同步定义、文案与稳定性检查。
- 保留错误原因链，在负责边界记录一次。业务拒绝与系统故障分级，接口请求日志通过请求 ID 关联；不打印完整请求／响应体或凭据。
- 入站回调记录渠道、事件 ID 和去重结果；出站调用记录意图、结果与耗时；任务按轮汇总，不用逐条 Info 淹没日志。
- 成功日志在事务提交后输出，回滚不报成功；幂等键只记录安全的短摘要。日志遵循项目统一格式；参考 Go 服务采用英文、小写、无句末标点。
- 业务审计、调用明细及带请求 ID 的业务排查记录只追加、永久留存，不增加自动清理逻辑；高价值流水防止覆盖，必要时用数据库守卫。持久测试业务记录同样按约定留存。
- 可重建的隔离单元测试夹具、一次性 schema 与构建产物可按测试生命周期清理；不把它们与持久业务记录或工程维护历史混为一谈。

## 契约与文档

- 契约先于实现，用户侧与管理侧 DTO、权限和路由明确区分；请求签名只能提高调用成本，不能代替授权。
- DTO 返回相关实体名称与关键属性，避免页面拿裸 ID 逐条补查；请求大小、错误结构、时间和单位保持契约一致。
- 项目事实、规则及执行结果分开写。修改结构、契约、业务边界时，同批更新对应文档，移除失效说明，不并存互相冲突的新旧方案。
- 常驻文档持续维护；需求／参考文档可按日期命名并记录创建日，不顺手改名既有文件。具体开发与交付见[开发与实测流程](开发与实测流程.md)，原因汇总见[playbook](playbook.md)。

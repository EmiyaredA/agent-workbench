## Redis 与业务缓存

- 没有业务缓存的项目不凭模板增加缓存层；已有强一致封装或模型装饰器时统一回源、失效与不存在结果，不能各处裸 GET/SET 或进程内 map 缓存业务事实。参考提到的 shared/cache 未随脚手架提供，需实际确认，不假装已有。
- 金额余量和库存不缓存，以数据库条件更新为准；强一致调用方可绕开缓存。设置只读快照、稳定目录输入不是业务缓存，outbox 暂存也不能充当业务读取来源。
- 先写库并提交，再失效所有受影响缓存；事务内模型不带业务缓存。清理失败记录并安排恢复，不能把已提交写入错误宣称为未发生；有专用缓存陈旧错误时沿用其处理约定。
- 新增行清“不存在”键；手机号／邮箱变化清新旧查找键；角色、会话、离职、封禁与成员关系变化立即级联失效，并验证下一次请求被拒，TTL 只作兜底。
- 键名隔离项目／账号，统一装配缓存装饰器和客户端生命周期；客户端与业务更新失败语义明确，不静默丢失已提交状态。

## 设计、确认与需求记录

- 新功能先写问题、规则与边界、改动范围、不做什么、验收标准和待确认项；涉及页面先有原型。用户明确要求实施即可记录为确认，不重复索取固定口令；未确认的设计不当作实施授权。
- 需求有文档时沿用 `docs/需求/进行中/`、`已完成/`、`原型/` 的生命周期；确认日期与实际状态一致，已完成不等于已上线。没有这些目录的项目沿用既有位置，不为小修复强建文档。
- 同一需求一份文档，开发记录在末尾追加，不另建重复报告；完成后记录确认／完成日期、代码与合并提交、设计差异和后续。当前规则并入系统设计，历史需求只作回溯。
- 小范围、不涉及金额、权限、状态迁移、结构、错误码、设置、通知或信息泄露的小改动可简化为问题、改法、原型与少量验收；涉及这些边界仍走完整设计与审核。简化实测未覆盖手机时，合入前补齐。

## 分支、提交与协作

- 新功能在独立 `feat/<需求名>` 分支／worktree 开发，保持主工作目录稳定；各执行者只改分配范围。缺陷与明确的小修复按项目主开发分支约定处理。
- 每完成能独立构建、验证的部分，在功能分支内提交一次；只暂存当前任务的文件或片段，不使用无差别 `git add -A`，提交后检查实际文件清单。
- 提交信息采用项目约定，参考格式为中文单行 `feat:`／`bug:`／`docs:`；不随意添加正文或署名。已做提交不 amend、reset、rebase、squash；修正用新提交，保留其他会话工作。
- 推送、开关 PR、合并、发布、触发／重跑／取消 CI、仓库权限与 secret 变更均需明确授权；账号、令牌、2FA 和新增访问权限不自行调整，不能打印或保存凭据值。
- 获授权推送前核对 workflow 触发条件，将已完成提交合并为一次推送，不以反复 push 验证本机可测内容；文档／注释是否跳过 CI 沿用项目触发策略，未经授权不改 workflow 或取消他人任务。GitHub 状态优先用已有登录的公开工具只读查询，权限不足如实说明。
- 用户授权合入后，先同步主开发分支到功能分支，处理冲突并重跑受影响验证，再按项目方式合入，记录合并提交；仅清理本任务已确认可清理的 worktree／分支，更新需求状态，不提前宣称上线。
- 跨会话可能改同一文件、接口或 schema 时，先确认交叉范围与基点；不要后台覆盖别人工作。删除用户文件须明确具体清单并获确认，移动／改名也不顺手扩大范围。

## 按职责使用宿主能力

- 分清任务拆解、开发、实测和独立审核职责；可独立且不争用文件的工作适当并行，不能为凑数量拆任务。宿主支持时使用独立执行／审核能力，不绑定 Claude、Codex 或具体模型版本，不另建模型调度平台。
- 每份任务给出目的、相关规则、验收条目、文件边界和基点；审核只读相关 diff，需要时追溯调用链，不要求每个执行者通读全部历史。
- 执行者交回提交号、文件清单、契约／结构变化、测试结果、设计差异、风险位置与未完成项；审核方核对真实 diff 和提交，不仅看汇报。
- 独立审核不可用时说明由谁检查及缺少什么，不能冒称已独立审核或冒报模型名。需额外工具、账号或能力才能达到验收目标时与用户协商。

## 实测准备与环境

- 使用最新代码，在未占用的测试端口与隔离状态启动，只管理自己创建的实例。验证已提交版本时避免混入其他会话未提交内容；只在前端有改动时重建相应资源，遵循真实构建依赖。
- 不连接线上或未知环境；检查短信、支付、通知和对象存储是否会产生真实副作用，未获授权不付款、不发真短信或推送到真实群。固定验证码不代表不会发送短信。
- 常驻测试数据由项目现有入口补齐；账号、令牌与可变 ID 从私有测试输出读取，不硬编码、不进 Git。状态破坏性测试另建带 `e2e-…-deletable` 等明确标记的数据。
- 测试数据通过公开接口创建；项目专用的管理员初始化、数据库夹具只在明确的隔离入口执行，不越权修改别的服务的数据。持久测试数据默认保留，确实影响测试时按标记清理并说明；记录留存遵循[工程约定](工程约定.md)。
- 共享通知／安全设置不按参考文档直接清空；需要调整先确认影响范围并使用隔离通道，测试结束恢复本任务调整的设置。无测试支付凭据只测到未开通状态，不能伪造支付成功。

## 接口、权限与页面验收

- 先按需求列完整验收清单，覆盖正常、错误、未登录、越权、数据不存在、重复请求、同键不同体、并发修改与必要审计。要求全量时按真实路由清单覆盖，不抽几个接口冒充全量。
- 接口可用真实 HTTP 请求核对期望／实际状态、方法、路径、结果摘要；本机 curl 使用 `--noproxy '*'` 避免代理绕向外网。核对本地化错误，不把消息 ID、驱动错误当作业务提示。
- 页面必须真实操作触发关键接口，核对网络响应、页面反馈与权威业务状态三者；只跑 curl 不算页面验收。可用宿主浏览器或 Playwright，不绑定特定 MCP；无可用能力时报告未验证与缺口。
- 管理接口覆盖普通用户 403、未登录／伪造身份 401；检查角色注入、篡改令牌、降权或封禁后旧会话、跨用户与跨租户资源隔离。鉴权状态以权威后端为准。
- 写操作后通过有权访问的数据入口核对结果；不得为了“查库”跨越数据归属。新增或改动系统设置，走管理页面修改、保存，再核对持久化与审计。
- 桌面与手机检查布局、可点区域和悬浮遮挡，主要点击目标至少 40px；涉及多语言时覆盖长英文。用隔离浏览器会话与测试账号，不共用用户登录态；同一流程尽量复用页面，换角色重新登录。
- 覆盖空值、超长与不换行文本、快速连击、重复提交、HTML／脚本／危险 URL 注入和契约请求上限；例如参考 API 非 multipart 上限 1 MB，超限应返回 413，目标项目以实际契约为准。
- 等待异步加载完成，断言仍在目标路由且未被登录页遮挡；修改浏览器持久状态后按实际生效方式刷新。通过后打开截图核对，不能只量数字或只信自动化摘要；证据放忽略的任务目录，不泄露凭据。

## 审核与收尾

- 分块交回先预检，整个需求完成后统一检查完整 diff；缺陷或明确小改动可交回即审。审核与实测在不争用状态时并行，二者均通过才宣称完成。
- 金额、权限、事务、迁移、错误码、信息泄露、缓存失效、审计及定义行为的文档是重点审核范围。已有分级／预筛工具才运行；源脚手架未提供的脚本不能当成已安装能力。
- 问题一次汇总，修复后核对同一规则其他出现处；复审围绕问题清单、增量和受影响行为，不机械重跑全部测试；出现新风险再扩大验证。
- 构建、相关单测、接口与页面实测、审核、文档更新和必要提交完成后再收尾；已有增量检查入口优先使用，不询问用户已授权的例行检查是否要做。
- 记录每个提交与文件范围、契约／结构变化、实际通过／失败／未执行、设计差异、待办及审核方式；没有需求文档的小修复在交接中记录同样事实。汇报先结论，未完成说明阻塞步骤，不用固定结束口号冒充完成。
- 只关闭本任务的测试实例、浏览器与后台任务，保留用户服务和其他会话；取消测试订单、恢复本任务设置，说明残留的外部对象及未验证内容。日志留档遵循现有 Skill，不重复记录同一修改。
